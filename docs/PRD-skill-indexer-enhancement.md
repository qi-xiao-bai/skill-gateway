# PRD: Skill-Indexer 全局调度与编排网关（透明代理直达 + 图谱驱动多技能串联编排）

## Problem Statement

在数字员工与大模型智能体生态中，技能（Skill）与工具（MCP）数量呈指数级膨胀（从最初十几个迅速增至数百个，覆盖研发、测试、代码清洗、代码评审、CRM 客服、数据分析等各个垂直领域）。但在实际应用中，用户与智能体平台面临着严重的结构性矛盾：

1. **选型心智负担沉重，技能难以被精准调用**：
   - 技能名称五花八门、入参格式复杂，普通用户无法记住数百个具体技能名（如 `crm-support`、`sfdc-copilot`、`minimax-pdf`、`plan`、`feature-dev` 等）；
   - 大模型在宽泛上下文中容易产生幻觉，挑错工具或在多个相似技能间反复试错，消耗大量思考轮次，导致用户等待时间成倍增加；
   - 缺乏统一入口，用户不得不手动输入 `@特定技能`，失去了自动化智能助手的核心价值。

2. **单兵作战孤立无援，复杂需求缺乏跨技能协同能力**：
   - 现存的所有技能均为单点能力切片（Single-purpose Skill），无法独立承接端到端复合任务；
   - 例如用户提出“开发一个完整的用户认证需求”，实际包含四个关键阶段：**需求理解与架构规划 $\rightarrow$ 特性设计与源码编码 $\rightarrow$ 代码去冗余与反AI味精炼 $\rightarrow$ 架构重构与质量审查**；
   - 缺乏编排机制时，用户必须手动依次调用各个技能，并在会话中反复复制粘贴上一阶段的产物。这不仅操作极其繁琐，还会导致严重的上下文断层与信息失真。

3. **传统度量指标脱离实战价值**：
   - 早期以“节省了 190 个无关技能的 Token”作为核心价值宣称，但在真实生产环境中，智能体平台本身就不会盲目加载无用技能；
   - 真正的痛点在于：**多跳中转带来的时间延迟**、**人工选型的认知摩擦**，以及**跨技能交付物无法自动流转**。

---

## Solution

将 `skill-indexer` 从早期的“静态目录检索工具”彻底重构升级为 **“智能代理直达 + 图谱驱动多技能串联编排网关”**，作为所有技能与工具调用的统一调度大脑：

1. **统一入口与透明代理直达（Transparent Proxy Gateway）**：
   - 用户只需呼叫 `@skill-indexer`，输入任何自然语言业务需求或单点任务；
   - 网关通过倒排内容索引与轻量元数据，秒级匹配最契合的目标技能，并**直接代理该目标技能的角色定位与专业规范回答用户**；
   - 用户获得与精准直调目标技能完全一致的高保真结果，消除人工选型与中间层转述套话。

2. **图谱驱动的多技能串联编排（Multi-Skill Pipeline Chaining）**：
   - 当检测到用户的任务为复合需求（如系统研发、故障排查、全量重构等）时，自动启动编排引擎；
   - 基于系统内建的**知识图谱拓扑边（`depends_on` 功能依赖、`contains` 包含、`similar` 语义协同、`overlap` 词重叠）**与通用工程生命周期模型，自动构建**有向无环图流水线（DAG Pipeline）**；
   - 明确定义每个阶段的“依赖输入”、“执行动作”、“交付产物”以及“上下文接力契约（Context Handoff）”，引导智能体按序推进，保证端到端闭环交付。

3. **真实可度量的提速留痕（Honest & Measurable Telemetry）**：
   - 单任务代理直达明确标注：命中的目标技能、消除的中转跳数、响应提速比例；
   - 多技能流水线明确标注：串联的阶段拓扑、各阶段交付产物、消除的人工选型与上下文断层收益。

## User Stories

### 核心能力一：透明代理直达 (Transparent Proxy)

1. As a 业务用户, I want 直接向网关提问业务问题（如“合同双签后的后续流程是”）, so that 我不用去查找哪个具体技能负责合同审批，直接得到该业务技能的专业解答。
2. As a 开发者, I want 输入“帮我写个数据清洗脚本”, so that 网关自动匹配对应的开发技能并代理生成高质量代码，省去手动翻阅技能清单的时间。
3. As a 智能体平台, I want 网关在代理执行时直接加载目标技能的关键指令, so that 大模型能够以最高保真的专业水准回答，而不是给出一层空洞的中转提示。
4. As a 终端用户, I want 网关在输出底部附带直达留痕脚注, so that 我清楚知道是哪个底层技能在提供支持，且确认调用未发生多跳漂移。
5. As a 平台管理员, I want 代理直达能够大幅缩短响应时间（减少 50% 以上的多轮交互轮次）, so that 系统吞吐量和用户满意度显著提升。
6. As a 终端用户, I want 支持显式提及（如 `@特定技能` 或 `使用「某技能」`）时自动剥离前缀并精准直达, so that 兼顾高级用户的指定调用习惯。

### 核心能力二：图谱驱动多技能串联编排 (Pipeline Chaining)

7. As a 产品经理, I want 输入“开发一个用户认证需求”, so that 网关自动为我规划 `plan` $\rightarrow$ `feature-dev` $\rightarrow$ `ai-slop-cleaner` $\rightarrow$ `code-review` 4 阶段流水线，而不需要我手动分别调用 4 个技能。
8. As a 运维工程师, I want 输入“排查线上接口响应慢和内存泄漏问题”, so that 网关自动串联 `systematic-debugging` $\rightarrow$ `plan` $\rightarrow$ `feature-dev` $\rightarrow$ `code-review` 故障诊断与修复流水线。
9. As a 系统架构师, I want 输入“对核心服务进行架构解耦与重构”, so that 网关自动编排架构评估、渐进规划、无损重构与一致性审查的技术债治理流水线。
10. As a 业务分析师, I want 输入“端到端处理季度销售单据并导出报表”, so that 网关自动编排数据检索、流程流转与结果导出的业务闭环流水线。
11. As a 开发者, I want 流水线具备拓扑可视化（Mermaid 流程图）, so that 我一眼看清阶段流向与技能依赖关系。
12. As a 开发者, I want 流水线输出明确的协同矩阵表, so that 我清晰了解每个阶段的执行技能、依赖输入与交付产物。
13. As a 智能体执行者, I want 流水线提供严格的上下文接力契约 (Context Handoff), so that 上游规划产出的 `implementation_plan.md` 能够精准注入下游编码阶段，避免上下文丢失。
14. As a 智能体执行者, I want 代码清理阶段承接编码阶段的全部源码产物, so that 去冗余技能能精准剔除 AI 虚浮结构与模板废话。
15. As a 质量工程师, I want 代码审查阶段承接净化后的代码与修改 Diff, so that 审查技能专注于架构规范、安全性与回归风险。
16. As a 平台开发者, I want 支持以标准 JSON 格式输出流水线 DAG, so that 外部自动化工作流引擎能直接解析并驱动多 Agent 并行执行。

### 核心能力三：知识图谱构建与拓扑遍历 (Knowledge Graph)

17. As a 技能架构师, I want 系统具备 `depends_on` 有向依赖边, so that 编排引擎能够识别哪些技能天然以前置规划或底层工具为前置条件。
18. As a 技能架构师, I want 系统具备 `contains` 父子包含边, so that 族根技能与其细分子技能能自动形成上下级调度链。
19. As a 技能架构师, I want 系统具备 `similar` 与 `overlap` 语义相似边, so that 当某个环节的主选技能不可用时，系统能自动推荐备选技能进行替换。
20. As a 平台运维, I want 流水线匹配算法结合图谱边权重加权, so that 选出的多技能链条具有强内在关联，而非死板拼凑。
21. As a 平台运维, I want 图谱支持质量审查与自动修复（孤立节点补边、方向冲突消除、高密度节点剪枝）, so that 编排引擎始终运行在健康的拓扑数据之上。

### 核心能力四：内容索引与知识预投喂 (Content Index & Knowledge Pre-feeding)

22. As a 检索用户, I want 倒排索引覆盖技能正文内容（Markdown 代码块感知与 Python AST 结构分段）, so that 能够通过具体实现代码或配置关键词反向命中所属流水线技能。
23. As a 智能体执行者, I want 具有依赖关系的技能自动进行知识预投喂, so that 在当前技能执行时无需再次发起耗时的跨技能文件读取。
24. As a 平台开发者, I want 预投喂内容明确标注来源标签（如 `[←目标技能]`）, so that 智能体能清晰分辨本技能规范与外部投喂上下文。

### 核心能力五：意图智能路由 (Intent Routing)

25. As a 普通用户, I want 使用日常自然语言（如“从规划到代码审查”、“帮我把功能做完”、“全流程优化”）, so that 意图路由器能够自动识别为流水线任务并调用编排引擎。
26. As a 普通用户, I want 使用疑问句式或单点操作（如“怎么触发”、“用法是什么”）, so that 意图路由器能够准确区分并分发至单点查询或代理直达。
27. As a 平台管理员, I want 意图路由器具备分级优先级匹配规则, so that 避免通用词抢占高优先级动作。

### 核心能力六：环境自愈与跨平台韧性 (Resilience & Portability)

28. As a 沙箱环境使用者, I want 在宿主目录被安全策略隔离时自动触发平台桥接, so that 无论在本地还是受限沙箱中，技能调度与编排网关均能自愈运行。
29. As a 新环境部署者, I want 交付包不携带本机硬编码路径的易失产物, so that 解压后即可在任意机器上一次性生成可用拓扑。
30. As a 开发者, I want 运行时如果未检测到索引能自动执行首次构建, so that 99% 的情况下无需手动敲击构建命令。

### 核心能力七：检索配额与规模化治理 (Retrieval Quota & Scale Governance)

31. As a 开发者, I want 检索系统在 Python 内存毫秒级内对 100% 技能全量打分, so that 绝不因草率初筛漏掉任何长尾专业技能，确保高召回率。
32. As a 智能体平台, I want 设置全局 Top-K 硬顶配额 (`MAX_RETRIEVAL_TOP = 20`) 与动态相似度阈值剪枝 (`MIN_RELEVANCE_SCORE = 0.35`), so that 过滤长尾低质噪音，防止外部入参失控撑爆上下文。
33. As a 终端用户, I want 当检索未命中（0 命中）时系统自动检测磁盘变动并执行定向增量更新, so that 新落盘或更新的技能立即可用，且不因全量重算造成卡顿。

### 核心能力八：黑名单机制与图谱可视化审计 (Exclusion & Dashboard Visual)

34. As a 平台管理员, I want 通过 `.skillexclude` 文件、配置文件或命令行 `--exclude` 指定黑名单规则（支持 glob 通配符如 `test-*`）, so that 屏蔽实验性或废弃技能，杜绝误推荐。
35. As a 系统架构师, I want 在交互式 D3.js 知识图谱 (`dashboard`) 中以红色虚线边框与半透明样式呈现已排除技能，并具备实时显隐切换开关, so that 能直观审计被排除技能及其图谱依赖关系。

## Implementation Decisions

### 模块划分与深层职责边界

1. **意图路由调度模块（Intent Router Module）**：
   - 职责：作为接收用户请求的最前哨，根据词法模式、动词短语及句型特征，进行二级决策分流；
   - 接口：接受任意自然语言输入，返回推荐的核心动作命令及候选命令集；
   - 决策点：将“复合研发动词 + 目标对象”强制提升至编排流水线动作，打破原有一律回退至列表浏览的低效模式。

2. **多技能图谱串联编排引擎（Pipeline Chaining Engine）**：
   - 职责：基于任务目标匹配生命周期模型，结合知识图谱多维关系边进行动态加权打分，组装有向无环图并生成标准化执行契约；
   - 接口：提供统一的任务编排接口，支持 Markdown 渲染输出与纯 JSON 机器结构化输出；
   - 决策点：抽象四大通用生命周期模板（研发交付、故障诊断、技术债治理、业务处理），每个阶段预置规范化的输入依赖、产出物类型与接力约定，避免硬编码不可迁移的静态流水线。

3. **双模式执行协议层（Dual-Mode Execution Contract Layer）**：
   - 职责：在大模型 Prompt 规范中确立“单点透明代理”与“复合流水线编排”的执行准则；
   - 决策点：彻底废除“节省了190个无关技能”的虚假指标宣称，全面转向以“消除人工选型”、“压缩中转跳数”、“阶段交付物接力”为核心的真实度量标准；将关键调度声明置于描述字段前 120 字符以内的最高优先级显示区。

4. **语义图谱拓扑与分层存储模块（Graph & Index Storage Module）**：
   - 职责：持久化包含五种边类型（依赖、包含、相似、同族、词重叠）的有向图谱结构，提供毫秒级节点边检索与双向拓扑寻径；
   - 决策点：维持元数据紧凑设计，避免在轻量索引中塞入冗长全文；全文通过按需分层映射在真正执行命中时调取。

5. **全正文倒排与跨技能知识预投喂模块（Content Inverted Index Module）**：
   - 职责：提供基于语法树与代码块感知的细粒度正文分块索引，并在有依赖关联的技能节点间预投喂核心规范片段；
   - 决策点：投喂内容严格限定在触发词、配置规则与快速入门等高密度段落，设置单节点投喂上限，防止上下文无节制膨胀。

6. **跨平台沙箱自愈与桥接模块（Platform Resilience Bridge Module）**：
   - 职责：探测文件系统可达性，在沙箱隔离工作区通过外部清单镜像机制完成拓扑自愈重构；
   - 决策点：采用读命令触发式自愈策略，消除用户的安装与初始化心智负担。

7. **检索配额硬顶与动态门槛剪枝模块（Retrieval Quota & Dynamic Pruning Module）**：
   - 职责：在全量索引内存评分的基础上，实施严格的输出配额控制（`MAX_RETRIEVAL_TOP = 20`）与长尾噪音动态剪枝（`MIN_RELEVANCE_SCORE = 0.35`，相对 Top 1 分数 25% 截断）；
   - 决策点：坚持“内存评分 100% 保证召回率，输出阶段严格截断防止上下文膨胀”的双重标准，既不漏掉专业工具，又守护数字员工的 Token 配额。

8. **黑名单过滤与图谱可视化审计模块（Exclusion Filter & Graph Visualization Module）**：
   - 职责：解析多级黑名单配置（`.skillexclude`、`config.json`、CLI `--exclude`，支持 glob 通配符），对命中技能在检索/问答/编排全链路执行屏蔽；在 D3.js 力导向图生成时赋予红色虚线与半透明样式，并提供前端交互显隐开关；
   - 决策点：将排除逻辑内聚在路径与检索核心层，图谱渲染采用元数据驱动（`excluded: true` 标记），实现兼顾运行时安全过滤与架构级全局审计。

## Testing Decisions

### 良好测试的定义与准则
- **只验证外部行为，不耦合内部细节**：测试必须从用户输入话术、CLI 返回结构、DAG 节点流向、配额截断、黑名单过滤及产物契约出发，不依赖内部临时变量或中间集合实现；
- **全生命周期与防护机制覆盖**：针对预设的 4 大通用场景、配额防线、黑名单规则及未命中定向更新，设计端到端验证链路。

### 重点测试模块与范围
1. **生命周期探测与场景识别**：验证各类任务短语能否准确映射至正确的生命周期类型；
2. **流水线拓扑组装与关键技能命中**：验证在研发场景下能否准确串联 `plan`、`feature-dev`、`ai-slop-cleaner`、`code-review`，且无重复节点；
3. **输出契约合规性**：验证输出文本中是否包含标准 Mermaid DAG 代码块、协同矩阵表及标准化官方留痕脚注；
4. **机器消费接口序列化**：验证 `--json` 标志能否输出符合规范的 JSON 结构，并包含 stages、skills 及 action 字段；
5. **意图路由精准度**：验证单点业务、指定技能、复合流水线不同话术的分流正确性；
6. **检索硬顶配额与动态剪枝**：验证即使请求 `top=100` 也严格限制在 `MAX_RETRIEVAL_TOP`（20项）以内，且长尾低分节点均被自动过滤；
7. **技能排除过滤与通配符**：验证 `.skillexclude` 及 CLI `--exclude` 精准屏蔽目标技能（含通配符 glob 匹配）；
8. **未命中动态增量更新**：验证检索 0 命中时触发磁盘变动探测与针对该查询的定向增量更新。

### 代码库既有参考 (Prior Art)
- 参考内容索引测试用例中的文本提取与断言设计；
- 采用标准单元测试框架 `scripts/test_pipeline.py`（8 个测试全部秒级通过，无外部服务依赖）。

## Out of Scope

1. **分布式跨主机 Agent 实时通信协议**：本期重点聚焦在单会话内智能体对多技能的编排与时序驱动，不实现跨集群/跨物理主机的 RPC 通信网络；
2. **代码实时运行沙箱虚拟化**：流水线负责生成代码并指引测试，但不负责虚拟化容器或微型操作系统的即时启动；
3. **云端中心化图谱数据库持久化**：全量图谱与索引采用纯文本与轻量 JSON 存储，不引入 Neo4j 或 MongoDB 等重型外部数据库，以确保 100% 的便携性与离线可用性；
4. **用户交互界面的复杂图形拖拽编辑**：仪表盘（Dashboard）专注于高保真只读力导向图呈现，不提供网页端的节点连线与画布编辑功能。
