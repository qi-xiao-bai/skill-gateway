# 治理机制与详细契约

本文件存放 SKILL.md 红线契约的展开说明与规模化治理机制细节。

---

## 红线契约展开

### 1. 前置探查铁律

- 基础大模型对宿主环境实际安装的技能处于绝对盲态。
- 凡通过本网关进入的任务，在获得本地技能检索结果之前，严禁使用宿主原生能力直接交付。
- 复合研发/项目构建/系统实现与多阶段任务：必须运行 `pipeline`，严禁用 `search` 替代。
- 单点业务查询与专业知识咨询：运行 `chat`。

### 2. 命中即采纳

- 本地命中技能时：Agent 必须采纳命中技能的规范与指导推进交付。
- 本地完全无匹配时：当且仅当 CLI 检索结果明确显示"当前环境未安装匹配技能（已触发实时增量感知且磁盘亦无更新）"时，方可降级为通用能力，并在交付开头输出：
  `[skill-gateway] 经检索本地技能库，当前环境未安装与本任务匹配的专业技能（已触发实时磁盘感知无更新），已自动降级为通用能力执行。`

### 3. 编排结果排除自身

- indexer 自身也在技能库中，pipeline 编排与检索结果必须排除 `skill-gateway` 自身，防止自环套娃。
- 实现方式：检索与编排阶段对结果集过滤 `name == "skill-gateway"` 的条目。

## 双模式详细契约

### 模式一：透明代理直达

1. Agent 运行 `chat "<问题>"` 或 `route`，获取推荐技能及关联知识。
2. 无需用户二次跳转，Agent 直接吸收目标技能能力并代表其给出最终答复。
3. 单技能命中时的强制联动：输出中包含由图谱边计算出的关联技能，Agent 必须将联动技能纳入执行上下文，形成"主领域技能负责实现 + 联动技能负责规范/审查"的协同方案。

### 模式二：多技能串联编排

1. Agent 运行 `pipeline "<任务>"`，输出 Mermaid DAG 图及阶段协同矩阵。
2. 四阶段严格执行上下文接力（Context Handoff）：
   - Stage 1（需求规划与架构）：调用规划类技能，产出架构决策与原子任务清单。
   - Stage 2（领域特性实现与落地）：承接 Stage 1 规划，产出源码与测试。
   - Stage 3（精简优化与去冗余）：承接 Stage 2 源码，剔除冗余模板与废代码。
   - Stage 4（代码审查与质量验证）：承接 Stage 3 净化代码，完成质量验证与交付。
3. 严禁以"待办事项/手工步骤"取代图谱流水线。

## 规模化治理机制

面对数百上千的技能库规模，网关内建以下治理体系：

### 1. 配额硬顶与动态门槛剪枝

- **高保真全量扫描**：Python 内存毫秒级内完成全部候选评分排序（5~10ms，0 Token 成本）。
- **Top-K 硬顶配额**：全局最大输出上限 `MAX_RETRIEVAL_TOP = 20`（`search` 默认 8，`chat` 默认 5）。
- **动态相似度门槛剪枝**：底线 `MIN_RELEVANCE_SCORE = 0.35`，截断低于最大证据权重 25% 的长尾低质技能（基准取名称加分/置顶提权之前的证据权重）。

### 2. 未命中按需增量更新

- `search`/`chat`/`pipeline` 未命中时，自动触发宿主目录与 MCP 配置探针。
- 若磁盘有新增或修改的技能，仅针对当前查询相关技能执行定向增量编译，无需全量重建。

### 3. 技能黑名单与排除机制

- 支持在 `skill_profile.json` 的 `exclude_skills`、根目录 `.skillexclude`、`skill_gateway.config.json` 的 `exclude` 或 CLI `--exclude` 声明屏蔽规则（支持通配符 glob）。
- 排除名单中的技能完全脱离检索、问答与流水线推荐池。

### 4. 图谱可视化排除节点控制

- `dashboard` HTML 的 D3.js 力导向图谱中，已排除节点以红色虚线边框、半透明暗色底色与专属提示标展示。
- 界面顶部配置 `[☑ 显示已排除技能]` 实时开关。

### 5. 用户画像专属体系

- 通过 `skill_profile.json` 统一管理固定扫描目录（`fixed_roots`）、严格模式（`only_fixed_roots`）、置顶常用技能（`pinned_skills`）与排除名单。
- 任何 `search`/`chat`/`pipeline` 执行前强制读取 Profile。
- 用户全局指令在问答与流水线最顶部强制输出 `📌 【用户重要指令】` 区块。
- 置顶技能在检索和流水线选型时自动获得加分倾斜并标记 `★ [常用置顶]`。

### 6. 自省进化规范

- AI Agent 理解用户意图后，通过结构化命令入库（`profile --add-directive`），无需手动改文件。
- 双层记忆库：`output/memory.md`（HOT 活跃层）+ `output/corrections.md`（纠偏审计日志）。
- 入库后自动联动执行对应子命令，形成自省闭环。

### 7. 主动自适应进化

- 后置无感决策钩子：每次操作完成后后台自省，不阻碍前置查询响应。
- 毫秒级物理指纹感知：通过 `os.scandir` 采集候选目录变动指纹，仅磁盘有变动时才触发增量索引。
- 心跳保鲜周期：按配置（默认 300 秒）定期保鲜。
- 高频技能自进化置顶：某技能**被真实使用**（用户显式 `detail` 查看全文 / 明确采纳；出现在检索结果里不算）累计达到阈值（默认 3 次）且尚未置顶时，自动晋升至 `pinned_skills`。
- 关闭方式：在 `skill_profile.json` 中设置 `"proactive_update": {"enabled": false}`。

## 换环境后扫不到技能（"0 项"）自愈策略

1. **宿主技能目录不可达**：运行 `python scripts/platform_bridge.py`；平台通道把技能导出到 `inputs/platform_skills.json`，桥接脚本自动将其落入镜像并生成索引。
2. **技能在磁盘上但不在常规路径**：运行 `python scripts/build_index.py roots` 排查；在 `skill_gateway.config.json` 中配置追加路径，或使用 `index --broad` 广域探测。
3. **外部清单直接灌入**：运行 `python scripts/build_index.py import skills.txt`。

## 致谢与设计来源

本技能为自主设计实现，参考以下开源理念：
- **AOCI（AI-Oriented Cognition Infrastructure）**：符号层与语义层分离、定长字段顺序、紧凑标签与硬性字符配额机制。
- **Understand-Anything**：稳定 ID 命名空间、关系边图谱固化、覆盖口径统计与 `.skillignore` 机制。
- **Livus-AI / Skills-MCP**：渐进式披露分层加载与零成本发现。
